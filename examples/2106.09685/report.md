# Review of: LoRA: Low-Rank Adaptation of Large Language Models

This report does what a referee does. First it reads the paper: what it claims, whether its numbers agree with each other, what is unsound, unclear or missing, and whether it can be reproduced from what it gives. Then it tries to recompute the results that can be recomputed.

## Key findings

- **Major concern:** The claim of 'no additional inference latency' is not empirically verified for LoRA;
- **Major concern:** LoRA is only applied to attention projection matrices (W_q, W_v);
- **Numbers consistent:** all 17 cross-checks of the paper's numbers agree.

*Each point is detailed below with its evidence.*

## Summary of the paper

The paper proposes LoRA (Low-Rank Adaptation), a method that freezes pre-trained language model weights and injects trainable low-rank matrices (A and B) into each Transformer layer's attention projections. This reduces trainable parameters by orders of magnitude (e.g., 10,000× for GPT-3 175B) while matching or exceeding full fine-tuning performance on RoBERTa, DeBERTa, GPT-2, and GPT-3. LoRA adds no inference latency because the low-rank updates can be merged into the frozen weights. The authors provide empirical analysis of rank deficiency, release a PyTorch integration package, and report extensive experiments on NLU and NLG benchmarks.

## Major concerns

**1. The claim of 'no additional inference latency' is not empirically verified for LoRA; only adapter latency is measured.** (evidence)

> Our simple linear design allows us to merge the trainable matrices with the frozen weights when deployed, introducing no inference latency compared to a fully fine-tuned model, by construction.

Suggested: Measure and report actual inference latency for LoRA (merged and unmerged) on the same hardware used for adapter latency tests.

**2. LoRA is only applied to attention projection matrices (W_q, W_v); the MLP layers are frozen and not explored.** (completeness)

> We limit our study to only adapting the attention weights for downstream tasks and freeze the MLP modules (so they are not trained in downstream tasks) both for simplicity and parameter-efficiency.

Suggested: Investigate whether applying LoRA to MLP layers yields further improvements or different rank-efficiency trade-offs.

## Minor concerns

**1. The scaling factor α is described as not tuned ('we simply set α to the first r we try and do not tune it'), yet different α values (8, 16) are used across experiments without explanation.** (clarity)

> We then scale ΔW x by α/r, where α is a constant in r. When optimizing with Adam, tuning α is roughly the same as tuning the learning rate if we scale the initialization appropriately. As a result, we simply set α to the first r we try and do not tune it.

Suggested: Clarify how α is chosen per experiment and whether it interacts with learning rate scheduling; report the α used for each main result table.

**2. The GPT-3 fine-tuning baseline is taken from the GPT-3 paper rather than reproduced, making the comparison less controlled.** (evidence)

> We take the GPT-3 few-shot result on RTE from the GPT-3 paper. For MNLI-matched, we use two demonstrations per class and six in-context examples in total.

Suggested: State explicitly which GPT-3 baseline numbers are from the original paper and which are from your own runs; if possible, run a fine-tuning baseline under the same low-data regime.
